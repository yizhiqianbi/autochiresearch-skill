## Overview

All data collection runs through the external survey platform. The researcher's job is to export CSVs from the platform on a regular schedule and store them locally under `projects/llm/output/`. No database, API, or server-side import process is involved. This document covers the export schedule, file-naming conventions, column mapping, import into the local analysis environment, and data-safety rules.

---

## File Naming Convention

Every file that enters `output/collection/` must follow this pattern:

```
YYYY-MM-DD_<type>_<status>.csv
```

| Placeholder | Allowed values | Example |
|---|---|---|
| `YYYY-MM-DD` | Export date (local date of download) | `2026-04-15` |
| `<type>` | `survey`, `interview_interest`, `incentive_contacts`, `pilot` | `survey` |
| `<status>` | `raw` (untouched), `raw_snapshot` (interim), `cleaned` (do not store in `collection/`) | `raw` |

Examples:

```
output/collection/2026-04-15_survey_export_raw.csv
output/collection/2026-04-15_interview_interest_raw.csv
output/collection/2026-03-22_pilot_export_raw.csv
```

Cleaned derivatives go to `output/analysis/`, never back into `output/collection/`.

---

## Export Schedule

| Phase | Frequency | Action |
|---|---|---|
| Pilot | Once, after pilot closes | Export pilot responses; review; delete from platform before main launch |
| Active collection | Every 2–3 days | Download `survey_export_raw.csv` with current date; keep all snapshots |
| Post-collection (final) | Once, day after closure | Download final `survey_export_raw.csv`; verify row count; archive |
| Interview opt-in | Once, after survey closure | Download `interview_interest_raw.csv`; never merge with survey data |

Keep all dated snapshot files. Do not overwrite earlier exports. Storage is cheap; losing data is not recoverable.

## Platform Export Steps (Wenjuanxing)

1. Log into the Wenjuanxing dashboard.
2. Open the survey project.
3. Click "数据" (Data) → "导出数据" (Export Data).
4. Select format: CSV (UTF-8 encoding; confirm this explicitly to avoid garbled Chinese characters).
5. Select all columns.
6. Download the file.
7. Rename the downloaded file to the naming convention above immediately upon download.
8. Move it to `projects/llm/output/collection/`.

If using Qualtrics, the equivalent path is: Data & Analysis → Export & Import → Export Data → CSV → Download.

Verify encoding after download:

```python
import pandas as pd
df = pd.read_csv("output/collection/YYYY-MM-DD_survey_export_raw.csv", encoding="utf-8")
# If garbled: try encoding="utf-8-sig" or encoding="gbk"
print(df.head(2))
```

## Import Script Template

Save this as `analysis/import_and_rename.py` and run it each time a new raw export arrives.

```python
"""
import_and_rename.py
Renames raw platform columns to canonical schema and saves a renamed file.
Does NOT apply exclusion logic (see analyze_fake_data.py for that step).
"""
import pandas as pd
import sys
from pathlib import Path

RAW_PATH = Path(sys.argv[1])  # e.g., output/collection/2026-04-15_survey_export_raw.csv
OUT_DIR = Path("output/collection")
OUT_DIR.mkdir(parents=True, exist_ok=True)

df = pd.read_csv(RAW_PATH, encoding="utf-8-sig")

# --- Edit this mapping to match your actual platform headers ---
RENAME_MAP = {
    "序号": "response_id",
    "提交时间": "submitted_at",
    "用时": "completion_seconds",
    # add all other platform-to-canonical mappings here
}

df = df.rename(columns=RENAME_MAP)

# Derive llm_used_any from U1 if platform exports it as a multi-select string
if "llm_tools_used" in df.columns:
    no_llm_value = "I have not used LLMs for career-related tasks"
    df["llm_used_any"] = df["llm_tools_used"].apply(
        lambda x: "No" if isinstance(x, str) and no_llm_value in x else "Yes"
    )

# Derive eligible_status from screener if not already present
# (customize based on how skip logic is exported)
if "eligible_status" not in df.columns:
    df["eligible_status"] = "Unknown"

out_path = OUT_DIR / RAW_PATH.name.replace("_raw.csv", "_renamed.csv")
df.to_csv(out_path, index=False, encoding="utf-8-sig")
print(f"Renamed file saved to {out_path}")
print(f"Shape: {df.shape}")
print(f"Columns: {df.columns.tolist()}")
```

Run as:

```bash
python analysis/import_and_rename.py output/collection/2026-04-15_survey_export_raw.csv
```

## Exclusion and Cleaning Steps

Apply these steps in order after renaming. Write the result to `output/analysis/cleaned_survey.csv` and log removals to `output/analysis/exclusion_log.csv`.

```python
import pandas as pd

df = pd.read_csv("output/collection/2026-04-15_survey_export_renamed.csv", encoding="utf-8-sig")

log = []

def exclude(mask, reason):
    global df, log
    dropped = df[mask]
    for _, row in dropped.iterrows():
        log.append({"response_id": row.get("response_id", "?"), "reason": reason})
    df = df[~mask]

exclude(df["consent"] != "Yes", "consent_not_given")
exclude(df.get("eligible_status", "") == "Ineligible", "screener_ineligible")
exclude(df["attention_check_1"] != "Agree", "ac1_failed")
exclude(df["attention_check_2"] != "Boiling water", "ac2_failed")
exclude(df["completion_seconds"].astype(float) < 180, "completion_too_fast")

df.to_csv("output/analysis/cleaned_survey.csv", index=False, encoding="utf-8-sig")
pd.DataFrame(log).to_csv("output/analysis/exclusion_log.csv", index=False)
print(f"Valid rows: {len(df)}")
print(f"Excluded rows: {len(log)}")
```

## Interview Contact File Handling

The interview opt-in is stored in a completely separate file. It must never be joined to the main survey CSV.

Workflow:

1. Export the interview opt-in form separately as `output/collection/YYYY-MM-DD_interview_interest_raw.csv`.
2. This file contains only: opt-in timestamp, preferred contact method, contact detail.
3. It does NOT contain `response_id` from the main survey.
4. To select interview candidates, use the `interview_opt_in` column in the cleaned survey (which only records "Yes" or "No") to count volunteers, then contact them through the separate form list in order of submission.
5. Record which volunteers were contacted and whether they scheduled an interview in a private researcher note, not in either CSV.

---

## Data Safety Rules

- The `_raw.csv` file is never modified. It is the archival record.
- All transformations are applied to copies; results are saved to new files.
- The `output/collection/` and `output/analysis/` directories must be added to `.gitignore` if this workspace uses git, to prevent accidental PII commits.
- If a cloud backup of data files is needed, use an encrypted folder or a storage service that complies with your institution's data management policy. Do not sync to a public GitHub repository.
- At study conclusion, retain the raw export files for the period required by your institution's IRB or ethics board, then delete them securely.
